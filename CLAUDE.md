# Cribbage — notes for Claude

Two-player cribbage to 121 in the browser, built for Tim to play on his iPhone and
laptop. You play the computer (easy / medium / hard). Online play against another
person is written but switched off: `js/firebase-config.js` is `null`, so no backend
is ever contacted. No accounts, no build step, no dependencies for the site itself.

- Live: https://timothyhadfield.github.io/cribbage/ (GitHub Pages from `main`, root folder)
- Repo: `TimothyHadfield/cribbage` (public). Footer link `../` goes to the Board & Card Games hub.
- Read `PROGRESS.md` first (state, decisions, gotchas). `README.md` explains the design.

## File map
- `index.html` — all markup and CSS; plain `<script>` tags in load order (online.js is the one ES module).
- `js/score.js` — scoring. `scoreHand` (itemised, for the UI) and `handValue` (fast, for the AI) are two implementations on purpose; tests cross-check them. Cards are integers 0-51.
- `js/engine.js` — pure state machine: deal, discard, cut, pegging (go / 31 / last card), show, 121 stop, skunks. `award()` is the only place points are added.
- `js/ai.js` + `js/crib-ev.js` — computer opponent; `crib-ev.js` is generated by `tools/build-crib-ev.js` (don't hand-edit).
- `js/local.js` — vs-computer transport. `js/online.js` — Firestore transport (host-authoritative). `js/app.js` — controller. `js/ui.js` — DOM builders.
- `firestore.rules`, `firebase.json` — rules for when online play is turned on.
- `test/` — plain Node tests, no framework.

## Run locally
`python -m http.server 8126` in the repo root (use the background option), then open http://127.0.0.1:8126/.
`App.current` in the console exposes the current game view, handy for scripted phone-view checks.

## Test
- `node test/score.test.js`, `node test/engine.test.js`, `node test/ai.test.js` — seconds each.
- `node test/exhaustive.test.js` — about 6 minutes: every one of the 12,994,800 hand+starter deals against an independent reference and the published score-frequency table, every pegging sequence, 20,000 whole hands refereed separately. Run it after any change to `score.js` or `engine.js`.
- `cd test && npm ci && npm test` — Firestore security-rules tests in the local emulator (no real project). Needs Java 21+ (firebase-tools 15 refuses 17); works on this laptop as of 2026-10-16.

## Deploy
Push to `main`; GitHub Pages rebuilds. `python ~/.claude/hooks/live-check.py <repo path>` waits for it.

## Standing instructions / decisions (from PROGRESS.md, don't relitigate)
- Host-authoritative online play on the free Spark plan; the host can see your cards. Accepted.
- Anonymous auth: "Nobody should have to make an account to play one game."
- `handValue` duplicating `scoreHand` is intentional. Log lines use the "Name: thing" form because one player is called "You".
- "Go" is automatic, not a button.
- Don't create the Firebase project: only Tim can (see PROGRESS.md "Authorized next steps").

## Traps
- Firestore rejects arrays of arrays: the show breakdown travels as `showItemsJson`; per-player lists are `pegPlayed0/1`.
- The matchmaking query avoids a composite index on purpose (one `orderBy`, filter client-side).
- `online.js` imports the Firebase SDK dynamically (top-level `await`) only when the config is set; keep it that way, or every visit downloads ~245 KB for nothing.
- The rules forbid listing `matches/*/private` even for the host, so cleanup deletes those docs by id.
- No test account exists (anonymous sign-in). Keep anything under `.claude/test/` out of git (it's in `.gitignore`).
